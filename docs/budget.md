# Бюджет производительности

Замеры — gzip, по `<script src>` в `out/index.html` (полифилы с `noModule` современные браузеры не грузят и в бюджет не входят).

## Базовая линия (пустой скаффолд, 2026-07-22)

| Сборщик | Все чанки | Полифилы (noModule) | Реально грузится |
|---|---|---|---|
| Turbopack (`next build`) | 186KB | внутри чанков | 186KB |
| **Webpack (`next build --webpack`)** | 167KB | 39.5KB | **~127KB** |

Решение: продакшн-сборка — webpack (`build` в package.json), dev — turbopack. Пол бюджета задаёт Next+React: ~127KB gz — меньше на этом стеке не бывает (для сравнения это цена выбора React; статический HTML рендерится без JS, гидрируются только 4 острова).

## Целевые значения

> **Про порог 125KB из плана.** В плане (Task 0.1 и Task 5.3) записано «≤ 125KB gz» — эта цифра выводилась из ожидания, что пол Next составит ~102–105KB. Фактический замер дал **127KB**, то есть 125KB недостижимы в принципе на этом стеке. Действующий порог — **150KB** из таблицы ниже; строки плана считаются устаревшими и заменяются этим документом.

- First Load JS (современный браузер): **≤ 150KB gz** (пол 127 + наш код островов ≤ 20KB + контент ~0: секции — Server Components)
- HTML главной: ≤ 40KB gz (база пустой страницы 3.1KB)
- Картинки hero-вьюпорта: ≤ 300KB суммарно
- Lighthouse: Performance ≥ 90 mobile / ≥ 95 desktop, Accessibility ≥ 95, CLS < 0.1

## Lighthouse по собранной статике (2026-07-27)

Замер на `out/`, поднятой сервером со сжатием и кэш-заголовками — как боевой nginx
(`scripts/qa-lighthouse.mjs`). На dev-сервере мерить бессмысленно: он отдаёт несжатые чанки
и HMR-клиент, баллы занижены и к продакшену отношения не имеют.

| Страница | Perf | A11y | Best | SEO | LCP | CLS | TBT |
|---|---|---|---|---|---|---|---|
| главная · mobile | **91** | 96 | 100 | 69¹ | 3.31с | 0.000 | 25мс |
| главная · desktop | **99** | 96 | 96 | 69¹ | 0.84с | 0.000 | 0мс |
| новости · mobile | 94 | 100 | 100 | 69¹ | 2.95с | 0.000 | 21мс |
| новости · desktop | 100 | 100 | 100 | 69¹ | 0.60с | 0.000 | 0мс |
| новость · mobile | 94 | 100 | 100 | 69¹ | 2.95с | 0.000 | 20мс |
| новость · desktop | 100 | 100 | 100 | 69¹ | 0.64с | 0.000 | 0мс |

Цели плана (Perf ≥90 mobile / ≥95 desktop, A11y ≥95) выполнены на всех страницах.

¹ SEO занижен единственным пунктом «Page is blocked from indexing» — это наша защита от
публикации с доменом-заглушкой. Со сборкой `NEXT_PUBLIC_SITE_URL=https://ai.rudn.ru`
**SEO = 100, ни одного провала**.

Что нашлось при этом замере и исправлено:

- **Сжатие.** Первый прогон дал Perf 81 и «Enable text compression — 780KB, 2100мс»: тестовый
  сервер отдавал без gzip. В конфиг nginx в README добавлены `gzip` и `Cache-Control` для
  `/_next/static/` — без них сайт на мобильном соединении теряет около 2 секунд и ~30 баллов.
- **Десятки 404 в консоли статической сборки.** Роутер предзагружает разметку соседних страниц
  плоским именем через точки (`__next.!KHNpdGUp.docs.$d$slug.txt`), а экспорт раскладывает те же
  данные вложенными папками. `build:static` теперь дописывает плоские копии — 49 файлов.
  Best-practices выросли с 96 до 100.
- **Двойная загрузка hero.** Обе ветки первого экрана лежат в DOM, и скрытая всё равно
  скачивалась. `loading="lazy"` на обеих (LCP держат `preload` с `media`) — минус 61KB на телефоне.

## Что изменила Фаза 5 в загрузке картинок

Главное открытие — не в отложенной загрузке, а в предзагрузке. React 19 автоматически поднимает
каждый отрисованный на сервере `<img>` без `loading="lazy"` в `<link rel="preload" as="image">`.
На длинной главной это давало **64 предзагрузки картинок** сразу при открытии: браузер тянул
высоким приоритетом всё до самого футера, конкурируя с LCP-изображением.

| Метрика | Было | Стало |
|---|---|---|
| `<link rel=preload as=image>` на главной | 64 | **5** (только первый экран) |
| Мобильный браузер грузит десктопное фото hero (1456w) | да, высоким приоритетом | нет (`preload` разделён по `media`) |
| Мобильный браузер грузит декоративные блобы десктопа | да, 54KB | нет |
| HTML главной (gzip) | 46.1KB | 48.1KB (+2KB — JSON-LD) |

HTML остаётся выше цели 40KB: страница длинная и целиком приходит в разметке (это плата за SSG
без клиентского рендера). `content-visibility` рассматривался и **отклонён** — на сайте якорная
навигация в шесть секций, а со свёрнутым содержимым плавный скролл к далёкому якорю приезжает
мимо цели; DOM главной 1312 узлов при пороге Lighthouse 1400.
