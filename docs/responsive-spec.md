# Адаптивная спецификация лендинга РУДН ИИ × X5 Tech

Макеты существуют только для двух ширин: **десктоп 1200** и **мобильная 320**. Они — эталон и замороженные точки: рендер на 320 и на ≥1200 не меняется никогда (контроль — пиксель-сверка).

## Стратегия v2 (2026-07-24, решение пользователя): чистое масштабирование от макетов

Между макетными точками ничего не перевёрстывается — раскладка ближайшего макета масштабируется пропорционально (`zoom`), поэтому на любой ширине вид ровно как в макете:

| Диапазон | Что показывается | Масштаб |
|---|---|---|
| **320–767** | Мобильный макет: канва 320px (`.canvas-320`) | `zoom = ширина/320` (1.00 → 2.40) |
| **768–1199** | Десктопный макет: калька 1200px (`.calque-1200`, для резиновых секций `.calque-fluid`) | `zoom = ширина/1200` (0.64 → 1.00) |
| **≥ 1200** | Десктопный макет 1:1, контент 1200 по центру | 1 |

Технически: `zoom: calc(100cqw / 320px|1200px)` (деление длин в calc даёт безразмерный коэффициент); `100cqw` от `main`/`footer` — не включает полосу прокрутки. Шапка НЕ масштабируется (резиновая, sticky): капсула ≥1024, бургер <1024.

**Ворота веток: мобильная/десктопная — 768px. Бургер → капсула: 1024px.**

## Типографика между базами

Заголовки: десктоп H1 42px → мобильный размер из мобильного макета (уточняется по каждой секции при вёрстке); между базами — без fluid-магии, ступенька на 768. Основной текст 13–14px одинаков везде. Никаких clamp() без необходимости — предсказуемость важнее плавности, это же упрощает пиксель-сверку.

## Что считается багом, а что — легитимным растяжением (320–430)

- Легитимно: выросли боковые поля контента, фото шире, строки текста переносятся в других местах.
- Баг: горизонтальный скролл, обрезанный текст, наложение элементов, изменение размеров шрифта/радиусов, «прыжок» раскладки.
