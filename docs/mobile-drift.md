# Мобильная вёрстка: сверка с актуальным макетом

Итог на 2026-07-27. Эталон — `figma-data/refs/new/mobile-271-2313.png` (320×19901), выгружен
из нового файла Figma вручную из редактора: REST API вторые сутки отдаёт 429 на все эндпоинты.

## Как это меряется

Пиксельный процент на мобильной вводит в заблуждение: на 320px текст занимает бо́льшую часть
площади, и подмена шрифта (Inter вместо X5 Sans, отклонение D2) даёт постоянный фон
несовпадения даже там, где вёрстка идеальна. Поэтому приёмка мобильной идёт по двум метрикам,
устойчивым к шрифту:

- **высота секции** — совпадает ли блок с макетным;
- **позиции полос контента** — `scripts/qa-bands.mjs` сводит оба изображения к списку строк
  текста, картинок и плашек и сравнивает их координаты.

Границы секций в макете размечены в `scripts/slice-mobile-new.mjs`: найдены поиском по профилю
и уточнены по замерам заголовков; тёмный футер служит точным якорем конца.

## Отклонённая правка

**06 «Как поступить»** остаётся на −6. Шаг этапа в макете на 1px больше нашего, и правка на +1
сводила высоту к +1 — но пиксельная сверка при этом ухудшалась с 8.74% до 10.63%: накопленный
сдвиг разводил строки текста по субпикселям. Шесть пикселей высоты дешевле двух пунктов
совпадения картинки, поэтому правка откачена (в коде оставлен комментарий с обоснованием).

## Что осталось

- **04, +7.** Одна таблетка дисциплины в макете 52px против наших 48 — это перенос текста, а не
  отступ. Дальше подгонять нечем без искажения раскладки.
- **07 «Преподаватели», −700** — решение D8, не дефект (см. выше).
