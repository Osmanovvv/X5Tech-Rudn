# План разработки фронтенда «РУДН ИИ × X5 Tech» — v2

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> v2 после адверсарной ревизии (33 агента, 26 подтверждённых замечаний — все внесены).

**Goal:** Пиксель-перфект фронтенд лендинга по Figma-макету (13 секций, десктоп 1200 + мобильная 320), со страницами новостей, SEO и PageSpeed ≥ 90, передаваемый клиенту папкой с README.

**Architecture:** Next.js (App Router) в режиме `output: 'export'` — статические файлы для любого сервера РУДН; путь к динамике остаётся (см. Task 4.5). Контент — в JSON (`site/content/`), компоненты только рендерят. Все секции — Server Components; `'use client'` разрешён ровно четырём островам: Header (бургер), NewsCarousel, LeadForm, ScrollReveal. Сторонние runtime-зависимости запрещены (маска телефона, карусель, анимации — руками).

**Tech Stack:** Next.js 16 + React + TypeScript, Tailwind CSS v4 + CSS-переменные, шрифты self-hosted через `next/font/local`, sharp для изображений, Playwright + pixelmatch для сверки.

**Правило качества (каждая секция):**
1. Эталон запрашивается из Figma ОДИН раз и сохраняется в `figma-data/refs/<node-id>.png`; повторные сверки — только с локальным файлом. Расхождение свежего скриншота Figma с сохранённым эталоном = дизайнер правит макет = **стоп и вопрос пользователю**, никаких молчаливых правок. При принятой правке — точечная перевыгрузка ctx одной секции.
2. Сверка инструментом Task 0.4 (не «на глаз»): браузерный скриншот секции на **1200** и **320** (мобильная база макета — именно 320, не 390) → приведение к меньшему размеру → pixelmatch; порог: десктоп ≤ 2%, мобильные полосы ≤ 3.5% (мобильный эталон существует только в масштабе 0.884 из-за лимита рендера Figma 16384px — растровые элементы дают шумовой пол ~2–3%; фактический замер шума: header 3.03% при визуально идентичной вёрстке). ## Фаза 3 — Анимации (переписана 2026-07-24 под спеку дизайнера)

**Источник правды — `docs/animation-spec.md`** (выгружено дословно из фрейма «анимация», node `372:2`
файла `u0YItwVIBhe1UFIhfsjiIs`). Прежняя редакция Фазы 3 была нашей выдумкой и отменена: дизайнер
прислал собственную спеку. Ничего не изобретаем — реализуем ровно её. Task 3.4 (скринкаст на
согласование) удалён: согласовывать нечего, анимации уже утверждены дизайнером.

Прототип-взаимодействий в Figma нет (проверено: 326 узлов, все `interactions` пустые) — значений
брать неоткуда, кроме текста спеки. Поэтому каждый параметр ниже — цитата из неё, а не оценка.

**Инварианты фазы (нарушение = баг):**
1. **Базовое состояние — видимое.** Без JS, до гидрации и при `prefers-reduced-motion` контент
   отрисован ровно как сейчас. Анимация только «улучшает». Иначе пиксель-сверка (Task 0.4) увидит
   пустоту вместо секции, и весь контроль качества посыпется.
2. **Конечное состояние = макет.** `enter viewport` заканчивается на `translate: 0 / opacity: 1 /
   scale: 1`. Замороженные точки 320 и 1200 обязаны остаться пиксель-в-пиксель (57/57).
3. **Только `transform` и `opacity`.** `width`/`height`/`blur` не анимируются (спека, «Что
   зафиксировать в ТЗ»).
4. **Пятый остров не заводить.** `'use client'` остаётся у четырёх: Header, NewsCarousel, LeadForm,
   ScrollReveal. Бюджет First Load JS ≤ 150KB (сейчас 128.9KB) — ScrollReveal должен быть ~1–2KB.
5. **Не смешивать эффекты на одном объекте** (спека: «Не смешивать одновременно fade, blur, rotation
   и scale»). Один узел — максимум `opacity` + одно преобразование.
6. **`data-reveal` не вешать на узел с transform-утилитами Tailwind.** Правило `[data-reveal]` живёт
   в `globals.css` вне слоёв, а нелейерный CSS сильнее любого `@layer utilities` — голое

### Task 3.1: Motion-фундамент (токены + остров ScrollReveal)

- [ ] `ScrollReveal` — один `IntersectionObserver` на всю страницу (не по обсерверу на элемент).
      **Наблюдаем смысловые группы (`[data-reveal]`: заголовочный блок, ряд карточек, фото), а НЕ
      секцию целиком.** Причина — замерено: на 320 при вьюпорте 640px секция «Программа обучения»

      всегда.
- [ ] Условие запуска (устойчивое к высоким элементам): `threshold: [0, 0.18]`, срабатывание при
      `isIntersecting && (intersectionRatio >= 0.18 || boundingClientRect.top < innerHeight * 0.85)`.
      Первое условие — буква спеки (15–20 % видимости), второе — страховка для групп выше экрана.
